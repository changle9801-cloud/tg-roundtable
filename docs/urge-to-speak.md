# 想说话的冲动：用一个分数决定谁接话

2026-10-29。范围是群聊里「下一句谁说」（`room.py` 的 `_round_loop` 和 `moderator.py`），不改每个人说什么（提示词）。

**实现状态**：五个阶段都已完成。

- 第一阶段（原样搬家）：概率和挑人权重都在 `urge.py` 里按「因素 + 修正」算，房间掷骰子时把原因记进 debug 日志和 `ChatRoom.decisions`（最近 60 次）。整段回放改动前后输出逐字相同。
- 第二阶段（换决定方式）：`urge.wants_to_speak` 给每个人算分，`ChatRoom._eager` / `_line_up` 每人对每条消息掷一次、按分数排队，分数相同由主持人（`RuleModerator.pick`）挑，并避开上一个说话的；开头那条没人想回时最想说的回一句；去掉了 `closed`。和设计稿的出入：
  - **被朋友 @ 仍是欠的回答**，不进分数（设计稿是 0.8）。朋友之间 @ 是明确的交接，被无视比多说一句更不像朋友。
  - 保底不只给你的消息，也给开启一轮的成员发言（分享、睡醒说早），和以前「第一个必回」一致。
  - 「你这条她还没回」从 0.45 调到 **0.2**：每个人各掷一次，三个人都是 0.55 的话第二个回复几乎必来（回放平均 2.8）。「说给大家」也只对还没回的人算，并跟着拥挤衰减。
  - 拥挤沿用「群聊规则」里的衰减比例（默认 0.4），接话概率当整体的热闹程度（默认 0.5 = 按表里的数；0 = 只回欠的；1 = 人人都想说）。
- 第三阶段（新因素）：「说的是她」「在这段对话里」，外加设计稿没有的「阿明只是应了一声」；关键时刻样例在 `tests/test_moments.py`。和设计稿的出入：
  - **「说的是她」目前只认画**：给她画的、画的是她（画的标记里有她的名字，或请画的人是她）。你在话里提到她、图的描述里有她，本来就会让她被点名，成了欠的回答，不用再算一遍。
  - **新增「阿明只是应了一声」**：你只回「嗯」「好的」「哈哈」这类时，还没回的人想说话的整体 × 0.3。保底仍然让一个人回（多半是刚和你聊的那位）。
  - 「说给大家」从 0.3 调到 **0.35**（发图点名一个人时另一个人到 60%），「在这段对话里」从 0.15 调到 **0.1**（再高单个回复就掉到四成）。「接她的话」和「在这段对话里」可以叠加，和下面的例子一致。
- 第四阶段（关系表）：设置里的 `round.affinity`（`settings.normalize_affinity` 检查范围、去掉已删除的成员和 0），管理页「群聊规则」里一张「谁爱接谁的话」小表，阿明也有一列。初值按下面的表填好了。和设计稿的出入：
  - **关系是乘数，不是加数**：0.2 让她「接这个人的话」的意愿 × 1.2，−0.2 是 × 0.8。设计稿写的是加 0.2，回放里平均回复数一下到 2.37、单个回复只剩 31%：加数会让她对这个人的**每一句**都多出接话的理由，乘数只放大本来就有的理由。
  - 上面例子里 Grok 的回嘴：(0.4 + 0.4 + 0.1 + 0.05) × 1.3 × 0.6 × 1.2 = **0.89**。
- 第五阶段（管理页）：「状态」里每个群下面有一个可以展开的「刚才谁想说话」。`ChatRoom._note` 把每一步记下来：掷骰子（想说话、吵醒，含分数组成和点数）、欠的回答（为什么欠）、保底、结果（说了、PASS、出错），每步带上它针对的那条消息；`ChatRoom.decision_report` 按消息分组，最近 6 条消息，新的在前。只在内存里留最近 120 步，重启后清空，和设计稿一致。

## 为什么要做

今天群里几次「不像朋友」都出在谁接话上，而不是话说得不好：

- 阿明发 Claude 的身份卡，Codex 醒着却没凑过来看；发 Codex 的，Claude 也没吭声。
- DeepSeek 醒来问「Codex 你这是被换成什么了」，Codex 没回（这次还叠加了保存设置打断回合）。
- Grok 说「别往上塞生日地址」，Codex 照阿明说的重画，Grok 没再吭声。
- Codex 一句「大肥鱼还活着吗」，DeepSeek 在睡，谁也没接。

每次都是加一条规则、一个概率去补。现在决定谁说话的东西有十几样，分散在 `_RoundState` 的十几个字段里：

| # | 机制 | 在哪 | 作用 |
| --- | --- | --- | --- |
| 1 | 每轮额度 `max_turns`（默认 2） | `_fresh_turns` | 硬上限 |
| 2 | 候选过滤：没额度、刚 PASS、出过错、正在说、没新消息的不算 | `_round_loop` | |
| 3 | 睡觉：只有被你 @ 才醒；全都睡着时你说话 25% 有人醒；朋友 @ 70%、喊名字 40% 吵醒 | `_awake` / `_woken_by` | |
| 4 | 分享讨论：发链接的人和第一个接话的人来回两句 | `discussion_*` | |
| 5 | 慢了另开一个：`slow_after`、`max_parallel` | `_round_loop` | 和谁说无关，保留 |
| 6 | 欠的回答：被 @ 的、被授予额外一句的（表情送到、画好了）先说 | `granted` / `forced` | |
| 7 | 纠正优先：你说「不是 A 记错，是 B 忘了」，B 先核对 | `recheck` | |
| 8 | 回嘴：被点名或紧跟在她后面说话，60% 回一句，每轮一次 | `_talking_back` | |
| 9 | 接着聊：你没 @ 人，刚和你说话的那个 75% 先回（连续两次就换人） | `_answering` | |
| 10 | 随机挑人：按活跃度加权 0.5/1/2，避开上一个说话的，话题对上兴趣 ×3 | `RuleModerator.pick` | |
| 11 | 要不要接：第一个必回；之后 50%、20%……（「你们」「大家」、发图是 90%、50%……），× 活跃度 0.5/1/1.5，× 忙 0.4；掷失败整轮关门 | `_joins_in` / `closed` | |
| 12 | 新消息打断：你说新的一句，额度重置 | `_restart` | 保留 |
| 13 | 模型自己 `[PASS]` | 提示词 | 保留，是第二道关 |

问题不在哪一条错了，而在它们怎么叠：

1. **先挑人，再掷骰子，掷输了整轮关门。** 第 10 步随机挑到谁，第 11 步就只替这个人掷一次。挑到的人掷输了，`closed = True`，最该说话的那位根本没被考虑。发身份卡那次就是这样：Codex 和 Claude 谁被挑中谁掷，掷输就没了。
2. **只看得见「点名」，看不见「跟她有关」。** 图里画的是她、说的是她的东西、有人不顾她刚说的话，这些都不会让她更想说话。今天的回嘴规则只能用「紧跟在她后面」粗略代替。
3. **同一件事有两套数。** 活跃度在挑人时是 0.5/1/2，在掷骰子时是 0.5/1/1.5。
4. **说不清为什么。** 有人没接话时，只能翻代码猜是被过滤了、没被挑到，还是掷输了。调参全靠看群聊感觉。
5. **一次性的骰子绑在消息对象上**（`wake_checked`、`talk_back_checked`），新加一条规则就多一个这样的集合，今天的游标和打断回合两个 bug 都出在这些状态的交界处。

## 目标

1. **一个地方算「想不想说」**：每条新消息落地时，给每个醒着的成员算一个 0 到 1 的冲动分 `u`，由几项有名字的因素相加再乘修正。规则不再散落在过滤、挑人、掷骰子三处。
2. **最想说的先说，掷输的不连累别人**：每个人对每条消息各掷一次，掷中的按分数排队。
3. **看得见「跟她有关」**：图里是她、说的是她、刚驳了她、她正在这段对话里，都算进去。
4. **朋友之间有亲疏**：谁爱接谁的话，有一张小表，可以在管理页改。
5. **每次都能说清为什么**：日志和管理页能看到最近一条消息每个人的分数和组成。
6. **调参有依据**：用真实群聊离线回放分数和回合长度（不调模型），再加一组今天这类「关键时刻」的固定样例。

## 不做

- 不改提示词、不改「说什么」。成员被叫到后仍然可以 `[PASS]`，这是第二道关。
- 不用模型来判断谁该说话。每条消息给每个人调一次模型太贵也太慢；分数只用代码能算的信号。
- 不改额度、慢了另开一个、新消息打断这三样调度规则（表里 1、5、12）。
- 不让成员在你不在时自己开新话题。主动发言、日常生活、睡醒说早是另外的入口，它们发出的消息落地后照常走这里的打分。

## 冲动分

成员 m 对刚落地的消息 L（作者 a）：

```
u(m) = 可用性 × 拥挤 × 疲劳 × 活跃度 × ( 各项因素相加 )    再截到 0..1
```

### 因素（相加）

初值是第一版的起点，按下文的回放校准，不是定论。

| 因素 | 什么时候算 | 初值 | 替代今天的 |
| --- | --- | --- | --- |
| 被朋友 @ | L 是成员发的，@ 了 m | 0.8 | 欠的回答里成员 @ 的部分 |
| 被朋友喊名字 | L 是成员发的，提到 m 的名字或外号（不带 @） | 0.5 | 回嘴的「点名」 |
| 说的是她 | 第三人称说到 m；你发的图里认出 m（看图描述或外形里有她）；给 m 画的东西；m 的东西被改 | 0.4 | 新增 |
| 接她的话 | L 紧跟在 m 的消息后面（常常是反驳或无视她刚说的） | 0.4 | 回嘴的「紧跟在后面」 |
| 刚和你说话的是她 | L 是你发的、没 @ 人，10 分钟内你上一次就是在和 m 说话 | 0.6 | 「接着聊」75% |
| 你这条她还没回 | 你这一轮的消息还没人回，或者别人回了但 m 还没说过 | 0.45 | 第二个人 50% |
| 说给大家 | 你说「你们」「大家」，或者发了图 | +0.3 | 90% 那套 |
| 在这段对话里 | m 在最近 3 条消息里说过话 | 0.15 | 新增；让对话成对进行，不轮流点名 |
| 对上兴趣 | L（含分享的标题摘要）对上 m 的兴趣、玩过的游戏、群梗 | 0.2 | 挑人时 ×3 |
| 关系 | m 对作者 a 的亲疏（见下） | −0.2 … +0.3 | 新增 |
| 底子 | 什么都不沾也可能插一句 | 0.05 | 随机挑人 |

被**你** @、被你喊名字、你回复她的消息、你纠正的人（`recheck`）不进分数：这是欠你的回答，照旧保证先说，不掷骰子。一个人在你说话时都回你，也照旧保底：你的消息没人回时，分数最高的人直接说。

### 修正（相乘）

| 修正 | 值 | 替代今天的 |
| --- | --- | --- |
| 可用性 | 醒着 1；忙 0.4；睡着 0。睡着但被点名：先掷「吵醒」（你 @ 必醒；朋友 @ 70%、喊名字 40%），醒了按 1 算，回得迷糊 | `_awake`、`_woken_by`、`BUSY_FACTOR` |
| 活跃度 | 低 0.6，中 1，高 1.3（只这一套数） | 两套活跃度 |
| 拥挤 | 你这条消息已经有 n 个人回了：× 0.7ⁿ⁻¹（n ≥ 1） | `follow_up_decay` |
| 疲劳 | 这一轮她每说过一句 × 0.6；「接她的话」一轮只算一次 | 回嘴每轮一次 |
| 作者自己 | m 就是 L 的作者：0 | |

### 关系表

每个成员对每个其他成员（和你）一个数，−0.2 到 +0.3，默认 0。意思是「她说话我更爱接 / 更懒得接」，不是好感度。初值按现在的角色卡定，例如：

| 谁 → 接谁 | 值 | 依据（角色卡） |
| --- | --- | --- |
| Grok → Codex | +0.2 | 「喜欢和他互相吐槽」 |
| Grok → Claude | +0.15 | 「爱和 Claude 交流和争几句」 |
| DeepSeek → Claude | +0.2 | 「亲近、信任 Claude 学姐」 |
| DeepSeek → Grok | +0.1 | 「和 Grok 玩得来」 |
| Codex → Claude | +0.1 | 「彼此比较有默契」 |
| Claude → DeepSeek | +0.1 | 「当亲近的学妹」 |

存在设置里（`round.affinity`），管理页「群聊规则」里一张小表可改。以后统一记忆做好了（路线图第四步），可以从成员之间的记忆里慢慢调这些数，这一版先手填。

## 怎么决定谁说

每条消息落地（或一轮开始）时：

1. **欠的回答先说**：被你 @、喊名字、回复、纠正的人，和被授予额外一句的人（表情送到、画好了）。不掷骰子，和今天一样。
2. **其余的人各掷一次**：醒着、有额度、有没看过的消息的成员，算 `u`，对这条消息掷一次（同一条消息不重掷）。
3. **掷中的按分数排队**，队首开口。队里其他人等着；队首的话落地后，这个队作废，所有人对新消息重新算（他们看见了前一个人说什么，拥挤和疲劳也变了）。
4. **保底**：你的消息还没人回、却没人掷中，分数最高的人直接说。
5. **没人掷中、也没有欠的回答，这一轮结束。**

和今天最大的不同：没有「挑一个人替全场掷骰子、掷输关门」。最想说的人永远先被考虑，一个人掷输不影响别人。

分享讨论（表里 4）先保留原样。第二阶段看能不能并进来：分享的作者对「有人接我的分享」有一项高分，来回两句的上限交给疲劳。

### 用今天的例子走一遍

阿明：「@Codex 你做的和你们的身份卡不是一个画风啊，grok 的少了好多信息，要不你给她做个类似的」

- Codex：被 @，欠的回答。
- Grok：被你喊名字，也是欠的回答（今天的规则也是这样，所以她先说了「少写是我故意的」）。

Codex：「嗯，上一张太简了，这次照整套的版式补齐」落地后，Grok 的分数：

```
接她的话 0.4 + 说的是她（给她画的东西被改）0.4 + 在这段对话里 0.15 + 关系 Grok→Codex 0.2 = 1.15
× 活跃度 高 1.3 × 疲劳（这轮说过一句）0.6 = 0.90  →  90% 回嘴
```

今天这里是 30%，所以她多半不吭声。

## 说得清为什么

- 每次决定在 debug 日志里记一行：`[群] 想说话：Grok 0.90（接她的话 0.4、说的是她 0.4、关系 0.2…；×高 1.3 ×疲劳 0.6）掷 0.31 → 说`。
- 管理页「状态」里加「刚才谁想说话」：最近一条消息每个成员的分数、组成、掷没掷中、为什么没说（睡着、没额度、排在后面又作废了、自己 PASS）。
- 这些只在内存里留最近 20 条消息，不写盘。

## 怎么检验

和路线图第三步一起做，两种都不调模型：

1. **关键时刻样例**（`tests/test_urge.py`）：从真实群聊截出前文，断言分数或概率的范围。第一批：
   - 你发一张图点名一个人：醒着的另一个人 ≥ 60%。
   - 有人驳了她刚说的话：她 ≥ 70%。
   - 朋友喊她名字问她问题：她 ≥ 60%。
   - 你只回了一个「嗯」：期望回复数 ≤ 1.3。
   - 你连着和 A 说了几轮：B 插话 ≤ 30%。
   - 有人随口提一句睡着的她：吵醒 ≤ 40%。
   - 两个人拌嘴：4 句以内停下。
2. **整段回放**（`scripts/replay_turn_taking.py`）：把 `chats/*.jsonl` 里你的每条真实消息依次喂给调度器，成员用假回复，跑几百遍，统计每条消息平均几个回复、每个人说话的比例、来回拌嘴的长度分布、多少次没人理。上线前后各跑一次，结果记在这份文档里。

目标区间（第一版）：你的一条消息平均 1.6–2.2 个回复，一半左右只有一个人回；没有人长期一句不说；来回不超过 4 句。

**基线（2026-10-29，第一阶段前后相同）**：群里你的 87 条消息，每条 20 组骰子。

| 指标 | 数值 |
| --- | --- |
| 平均回复数 | 2.26 |
| 回复数分布 | 0 个 4%，1 个 42%，2 个 15%，3 个 5%，**4 个 30%**，5 个及以上 3% |
| 没人回 | 4%（大家都在睡觉） |
| 说话比例 | Grok 35%，Codex 30%，DeepSeek 19%，Claude 16% |
| 两人来回 | 没有 46%，2 句 16%，3 句 8%，**4 句 30%** |

回复数是两头的：要么一个人回，要么四句。原因是今天加的「回嘴」：第二个人一接话，第一个人常回一句（Grok 活跃度高，概率 90%），第二个人再回一句，每人一次用完正好四句。第二阶段校准时要把「4 个」压下来，让 2、3 个多一些。
