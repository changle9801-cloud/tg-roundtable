# 日常聊天口吻调整

用户反馈 Grok 和 DeepSeek 的回复像助手或写稿，缺少自然聊天感。调整保留角色身份、兴趣、目标和历史，重点减少发言稿式上下文与固定表演要求。

- 公共聊天提示词只放简短的个人近况，不默认塞入作品正文、完整个人任务和私聊档案。私聊继续由每轮检索提供；追问笔记、作品等具体内容时，才给作者补充相应正文摘录。
- 后台个人活动仍保留完整的私有日常上下文，创作续写与目标推进不使用精简的聊天版本。
- 共用聊天规则缩短，去掉“修仙呢”等固定对照台词。梗库是可选的历史玩笑，不要求每次接梗，也不把旧笑话当作对人的固定判断。
- Grok 与 DeepSeek 的 style 更偏随口接话；关系字段去掉“随便损、抓把柄”和固定跟随起哄的要求。当前口吻与关系随每轮输入传递，旧 CLI 会话也能读到调整。

验证：364 项测试通过，新增验证覆盖作品正文按需进入当前聊天、作者隔离、后台完整上下文保留，以及旧会话接收到当前口吻。使用相同情境进行了第一轮 12 次隔离对照和第二轮 6 次候选试聊，未向 Telegram 发送测试消息。

样本观察：第二轮 Grok 能在澄清后简单接住事实；DeepSeek 的近况回复变为普通短句。不过有些样本仍会机械反问或出现刻意的修辞。少量试聊只能支持这一轮调整，不能证明所有后续回复都会自然。

对照脚本：`scripts/compare_casual_chat.py`。它使用运行中的服务作为基线，需要基线仍保留调整前的模板和日常上下文；配置改变后应重新准备比较基线，不能把脚本作为长期自动评分工具。

## 2026-10-29：减少段子、解释和总结

用户要求继续调整 Grok 与 DeepSeek，让回复更像熟人之间随口聊天。本轮修改两位成员的 `style` 和 `examples`，保留身份、关系、兴趣、模型及参数。普通闲聊允许一个反应就结束；明确追问原因、细节或故事时仍可展开。当前语气示例随每轮输入送入旧会话。

发现共用规则要求“新的、有意思的内容”才发言，而每次系统提示又携带完整旧梗和大事记，容易把普通回应加工成段子。本轮明确允许普通回应，公开会话只按当前消息检索相关旧梗与往事。档案继续保存，后台活动仍能读取完整记录。匹配忽略角色名称和口吻说明，避免仅因出现“Claude”就带出相关旧事；最多取三条梗和两条往事。

日终整理也补充约束：一次澄清、道歉或忘记内容不自动成为新梗，不给角色规定固定台词。

验证：386 项测试通过。五类情境做调整前后双轮对照，随后增加新的生活情境，并在原隔离会话中续聊；累计 84 条真实模型回复，无接口错误，没有发到 Telegram。机械测试只证明上下文与服务链路，主观效果与残余问题见 [本轮回放记录](natural-chat-replay-2026-10-29.md)。

新脚本 `scripts/replay_casual_dialogue.py` 使用固定的设置、已渲染提示与记忆快照，支持继续隔离的旧会话。当前服务已加载新配置，四位启用成员状态正常，聊天、会话、日常记录、旧梗与大事记的哈希保持一致。Claude 两项额度仍为 0（不限每日次数）。
