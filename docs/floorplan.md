# 自由户型和多层（C、D）设计稿

2026-10-30。八个决定阿明已确认（见文末）。家具系统见 `docs/furniture.md`，整体方向见 `docs/nookling.md`。

**实现状态**：C1、C2 完成。

- `floorplan.py`：按原来的自动排法给每个房间算出位置（`at`）、把三条走廊变成三个走廊房间（`kind: "hall"`）、把房间自己的门换成房子里的门；算一扇门连着哪两个房间、哪些房间从大门走不进去；新房间自动找位置（先贴着走廊、房子尽量紧凑、不堵大门）并在共用墙中间自动开一扇门。
- `home.json` 升到第 3 版：房间多了 `at`、`level`、`kind`，新增 `doors`、`floors`（现在只有「一楼」）。老房子第一次启动时转换一次；家具、位置、外形、翻日记记录、房间名都不动。新成员的卧室接在卧室那一排最右边，前面的走廊自动拉长、自动开门；「加一间」的新房间按上面的规则放。删房间时它的门一起删。家具检查改成看房子里的门。
- 页面按位置画房间、按门开洞；走廊和以前一样只有地面、没有墙和名字。走路改成按门找路：从一个房间经过门走到下一个房间，一直到目的地；出门、回家都走有大门的那个房间。
- 真实的房子已转换：12 个房间（3 条走廊）、12 扇门，每扇门都连着两个房间（大门连着客厅和外面），所有房间都走得进去；转换前后截图看不出差别。
- **C2**：
  - 页面在格子上找路（A*）：只走房间里的格子，绕开挡路的家具（地毯、画框不挡），只从门穿墙，同一个房间里可以斜着走但不切墙角；走到或离开的那件家具（沙发座位、床中间）本身可以进出。路线只留拐弯的点。格子上找不到路时，退回 C1 那种按门走直线的走法。
  - 从大门走不进去的房间（没有门，或者门只通向同样进不去的房间）：后端不再把成员安排进去（不去用那里的家具，歇着、找人都改去客厅或打电话）；页面上地面变红、名字后面加「（进不去）」，侧栏「家里」上面写明哪些房间进不去、要开门。
  - 实测：在真实的房子上算了几条路（卧室到书房电脑桌、厨房到娱乐室沙发、客厅到 Grok 的床上、床到厨房餐桌）和 9 个房间两两之间的 72 条路，沿路每 5 厘米检查一次，没有一条穿家具、穿墙或走出房间；在后台标签页里去掉书房的门，书房变红、标「进不去」、侧栏有提示、门洞合上。

和设计稿的出入：

- **后台标签页里看不到走路动画**：浏览器把后台标签页当成隐藏，页面不画动画（为了不占资源），人只在截图那一下动一点。所以 C2 的「绕开家具」是把算出来的路线逐点检查的，不是看动画。

和设计稿的出入（C1）：

- **楼层字段叫 `level`，不叫 `floor`**：房间的 `floor` 在 2e 已经用来存地面的样子了，再拿来当楼层会把地面的样子覆盖掉（上线前发现的）。门也是 `level`。
- **门落在整格上**：原来的门是按墙中间放的，有时会落在半格上；现在门的左端在整格，所以卧室、书房等的门往旁边挪了半格（四分之一米），看不出来。
- **走廊和走廊之间是「开口」**：中间那条竖走廊和两条横走廊之间记成宽 3 格的开口（`open: true`），不画门。
- **这一步还不绕家具**：房间都是长方形，在一个房间里走直线不会穿墙，但会穿过家具；绕开家具是 C2 的事。

## 要解决什么

现在的房子是程序自动排的：卧室一排、书房和娱乐室一排、厨房客厅储物间一排，走廊也是自动生成的。所以：

- 房间不能挪、不能拉大，只能在最后一排后面接新的；
- 门是写死在某面墙中间的，不能自己开；
- 只有一层。

阿明想要的是：房间可以自己摆、自己扩，能有二楼、三楼。

## C：自由户型

### 房子是一张格子图

- 每一层是一张格子图，格子还是半米一格，和家具用同一套格子。
- **每个房间有自己的位置**：`"at": [列, 行]`（房间左上角在这一层的哪一格）加上原来的 `"size": [宽, 深]`。同一层的房间不能重叠，可以挨着（共用一面墙）。
- **走廊也是房间**：`"kind": "hall"`，名字叫「走廊」，和别的房间一样能挪、能拉、能删，只是默认不摆家具、成员不会在里面「歇着」。现在那两条横走廊和中间那条竖走廊变成三个走廊房间。

```json
{"id": "study", "name": "书房", "level": 0, "at": [0, 13], "size": [18, 12], "kind": "room"}
{"id": "hall-1", "name": "走廊", "level": 0, "at": [0, 10], "size": [40, 3], "kind": "hall"}
```

### 门

- 门不再属于某个房间的某面墙，而是**房子里的一件东西**：在某一层、某条格子线上、宽 3 格。
- 门只能开在**两个房间共用的墙上**（连通两个房间），或者**一楼的外墙上**（大门，通到外面）。
- 一个房间至少要有一扇门，不然成员进不去；没有门的房间在页面上标红，成员不会被安排进去。

```json
{"id": "d-1", "level": 0, "line": "z", "at": [4, 10], "width": 3}
{"id": "front", "level": 0, "line": "z", "at": [19, 40], "width": 3, "outside": true}
```

（`line: "z"` 是横着的墙，`at` 是门左端的格子坐标。）

### 成员怎么走

- 现在走路是写死的路线（出门 → 走廊 → 中间那条竖走廊 → 另一条走廊 → 进门）。户型自由以后换成**在格子上找路**：只能在房间里走，只能从门穿过墙。
- 走路还是只在页面上画，后端只记她在哪个房间、在用哪件家具，这一点不变。
- 找不到路（房间没门、门被家具堵死）时，她直接出现在目的地，页面上提示「这个房间进不去，看看门」。

### 怎么编辑

「布置家具」里加一个「户型」模式，俯视、显示格子：

- **挪房间**：拖房间中间，整间房连家具一起挪；不能和别的房间叠在一起。
- **改大小**：拖房间的边。变小时如果切到了家具，拒绝并说哪件放不下（先把家具挪开）。
- **门**：点两个房间共用的墙，在那里开一扇门；点门可以删掉或拖着沿墙挪。把两个房间拖到挨着时，自动在共用墙中间开一扇门（可以删）。
- **加房间、加走廊**：在空地上拖出一个矩形，选「房间」或「走廊」，起名字。

### 旧房子怎么过来

第一次启动时按现在的自动排法算出每个房间的位置，写进 `at`，三条自动走廊变成三个走廊房间，原来写在房间上的门换成房子里的门。页面看起来和现在一样。之前在第三排后面另起一排的情况（左边那条过道）也一起换成走廊房间。

## D：多层

### 楼层

- 房子有一个楼层列表：`"floors": [{"level": 0, "name": "一楼"}, {"level": 1, "name": "二楼"}]`，楼层名可以改。
- 每个房间、每扇门、每件家具都属于某一层（房间的 `floor`；家具跟着它的房间）。
- 一层大约 3 米高，画的时候二楼整体抬高 3 米。

### 楼梯

- 楼梯是一种**家具**（新模板「楼梯」，占地比如 3×6 格），摆在某一层的房间或走廊里，写明通到哪一层。
- 上一层同样的位置必须是某个房间或走廊（楼梯口），摆的时候检查；上一层那块地方画成楼梯口，不能摆别的家具。
- 成员要去别的楼层：找路到楼梯底 → 爬上去（画成沿楼梯走）→ 从楼梯口继续找路。

### 看的时候

- 页面右上角有楼层切换：一次看一层，下面几层淡淡地显示在下方，上面几层不画（不然挡住）。
- 侧栏的「家里」列表照样显示所有人，在别的楼层的标一下「二楼」。点她会切到她那一层。
- 新加一层是空的，要先摆一架楼梯才能上去；卧室、书房都可以放在楼上。

### 大门和外面

- 大门只在一楼外墙上。出门的人从大门走出去消失，回来从大门进来，和现在一样。

## 对其他部分的影响

- **后端**：房间多了 `floor`、`at`、`kind`，门变成单独的列表，楼层列表；家具检查不变（家具在房间里的格子坐标不变）。按功能找家具时，同一层的优先，再找别的层。
- **成员的提示词**：「你住的家」那一段会写有几层、每层有哪些房间（第 3 步还会让她们知道自己在哪、谁在哪）。
- **墙和高度（B）**：多层以后楼上楼下的墙会互相挡。C、D 先用现在的矮墙；B 做完全高的墙时再一起处理「挡住视线的墙变透明」。

## 分几块做

| 块 | 内容 | 验收 |
| --- | --- | --- |
| C1 | 房间有位置、走廊变成房间、门变成单独的东西；页面按位置画；旧房子转过来 | 前后截图一样；数据重启后还在 |
| C2 | 在格子上找路；没门的房间标红 | 成员从卧室走到书房绕过家具、穿过门；删掉一扇门后能看到提示 |
| C3 | 户型编辑：挪房间、改大小、开门删门、拖出新房间和走廊 | 拉大客厅、把书房挪到别处、给它开新门，成员照样走得过去；切到家具、叠在一起、没门会被拒绝或提示 |
| D1 | 楼层列表、楼梯家具、楼层切换、楼梯口 | 加一个二楼、摆楼梯、在二楼拖出一个房间；页面能切楼层 |
| D2 | 跨楼层找路和爬楼梯 | 把一个人的卧室放到二楼，她睡觉时从客厅走楼梯上去 |
