# 家具系统（第 2 步）设计稿

2026-10-30。七个决定阿明已确认（见文末）。

**实现状态**：2a 到 2f 都完成了，家具系统（第 2 步）做完。

- `furniture.py`：19 种内置家具（现在房子里的每样东西），摆放检查（不出房间、挡路的不叠、门前 2 格留空、朝向只能 0/90/180/270），默认摆法，座位换算（`spot`）。
- `home.json` 升到第 2 版：房间带 `size`（格）和 `doors`，新增 `pieces` 和 `types`（自己做的种类，2d 用）。老的房子第一次启动时按默认摆法布置一次，改过的房间名、位置、外形、翻日记记录都不动。新成员的卧室自动带床、书桌（日记本在上面）、落地灯、地毯。`Home.place / move / remove` 已经能用并带检查，网页接口等 2d。
- `/api/home` 多返回 `pieces` 和 `types`；页面按数据画：房间按大小排，家具按模板画，门按数据开洞。

- **2b**：日常活动开始时，后端按功能名找家具：看东西、写东西找挂 `web.read` 的（电脑桌），玩游戏找 `game.play`，往群里发找 `chat.telegram`，真的开始看视频（调用看视频工具那一刻）找 `video.watch`。先找她所在的房间，再找公共房间，再找她自己的卧室，**不进别人的卧室**；都没有就按原来的规则去书房、娱乐室、客厅。位置里多记一个 `piece`（她在用哪件家具），页面让她坐那件家具的座位；是屏幕就找朝着它的座位；都没有就站在它正面前面。新动作「在看视频」（`watch`）。群聊里调用工具时走过去，要等 2c。
- **2c**：
  - 功能连接存在 `settings.json` 的 `functions`。从没设过时按工具自己能做的事自动连：能 `read_post`/`read_feed` 的连 `web.read`，能 `watch_video`/`search_videos` 的连 `video.watch`。连着已删除工具的会被清掉。
  - 「工具」页面每个工具多了「家里的功能」：选一个内置功能名、已有的功能名，或者起一个新的（像 `music.play`）。
  - 没连到任何功能的启用中的工具，在储物间里有一个纸箱（「还没拆箱：某某」，功能名是 `tool.<工具 ID>`）。在「工具」页面给它选一个功能，纸箱就消失（拆箱）。纸箱没拆时她用这个工具，会走到储物间的纸箱前面。在家里点纸箱，侧栏会说怎么拆。
  - 三个 CLI 报告工具调用时带上工具服务器 ID（`ToolActivity`：还是原来那句「正在用某某」，多带一个 `server`）。群聊里和日常活动里调用工具，她都会走到挂着对应功能的家具跟前；看视频的工具让她去电视前，读网页的让她坐到电脑桌前。
  - 群聊里用工具只换位置，不算「正在忙」，回完话也不会一直显示在忙；人在外面或在睡觉时不动。
  - 挂着的功能现在都没人能做（比如对应的工具停用了）的家具画成灰色；内置功能（游戏、画画、日记、搜索）总是能用，`chat.telegram` 要 Telegram 连着。
  - 新动作「在用东西」（`use`），给用了自定义功能工具的时候。
- **2d**：「家」页面右上角的「布置家具」：
  - 画面转成俯视、显示格子；拖家具换位置（可以拖到别的房间），松手就存；放不下、挡门、叠在一起的被退回原处并提示原因。点一下选中（橙色框），侧栏里可以转 90°、改颜色、改名字、勾选挂的功能、删掉。
  - 「添加家具」：选种类和房间，放到那间房第一个放得下的地方，再拖。
  - 「我做的家具」：新做一种（选样子、名字、占地格数、高度、颜色、默认功能），或者把内置的复制一份再改。座位按样子和大小自动算；复制来的家具形状不变时保留原来调好的座位。改大了以后放不下的、家里还摆着的，都会被拒绝并说明原因。编辑框里有一个转着的小预览。
  - 模型：编辑框里上传 `.glb`，服务器检查后存到数据目录的 `home/models/`（登录后才能读），显示大小、面数和动画名，面数超过 10 万提醒手机可能卡。可以转 0/90/180/270 度、调大小（0.2–3 倍）。模型按占地和高度等比缩放、放在地上、居中；加载失败就退回样子。
  - 房间：加（小 5×5、中 7×6、大 9×6 个单位）、改名（最多 8 个字）、删（空的、不是卧室、不是客厅、没人在里面）。新房间接在第三排末尾，排满了另起一排，前面加一条走廊，左边加一条连起所有走廊的过道。
  - 内置的 21 种样子：床、沙发、单人沙发、椅子、懒人沙发、书桌、电脑桌、桌子、餐桌、书架、衣柜、电视、冰箱、柜台、落地灯、盆栽、地毯、画框、海报、纸箱堆、纸箱。
- **2e**：
  - 每个房间的「外观」（布置模式下房间列表里的按钮）：地面、墙面各自可以是颜色，或者一张上传的图片像地砖、墙纸那样重复铺开，可以设一张图铺多大（0.25–5 米）；「用默认的」恢复原来的颜色。存在房间的 `floor`、`walls` 里，重启后还在。
  - 壁画：画框、海报、地毯可以放一张图片（选中后在侧栏里「放一张图片」），画框里的画、海报、地毯面就显示这张图；「去掉图片」恢复颜色。
  - 图片只收 PNG、JPG、WebP（按文件开头的字节认，不看扩展名），最大 5 MB，存在数据目录的 `home/images/`，登录后才能读。
- **2f**（开始前补定：设置换结构并自动转换、客厅放一台新电脑、点电脑能改且旧的地方先留着）：
  - `settings.json` 里原来顶层的 `telegram` 搬到 `apps.telegram`，给以后的 Discord 等留位置。启动时发现旧格式就先把原文件存成 `settings.before-apps.json`（只存一次），再写成新格式；token 还在 `secrets.json`，没动。
  - 新的内置家具「家里的电脑」（电脑桌的样子，屏幕是绿的），挂着 `chat.telegram`，默认在客厅左墙边。新房子自带；老房子第一次启动时放一台（`home.json` 的 `extras` 记一笔，之后被删掉也不会再放回来）。成员自己往群里发东西（日常里的 share）时走到这台电脑前；群里回话还是用随身的手机。
  - 在家里点电脑的屏幕（或在布置模式选中它点「Telegram 设置」），打开 Telegram 设置：谁来收消息（兼任某个成员的 bot 或单独的总控 bot）、总控 token、每个成员的 bot token、允许的用户和群。token 只显示末尾几位，留空不改。「群聊规则」和「成员」里原来的地方还能改，加了一句说明。
  - 真实数据已转换：`apps.telegram` 和原来的 `telegram` 一模一样，其他设置只多了第 2c 步的功能连接和工具路径修正；重启后 Telegram 显示运行中，四位成员都正常。

和设计稿的出入：

- **「新家具会被用」没有在真实的家里让成员跑一遍**：真实的日常活动可能会自己决定往群里发东西，所以只在副本上用真的模型调用验证，真实的家里只验证了摆放、拖动和挂功能。
- **顺手改掉一个真实 ID**：「群聊规则」里允许的用户输入框的示例写着一个真实的 Telegram 用户 ID（从第一次提交起就在），改成了 `123456789`。旧的提交里还有它，公开前清理历史时要一起考虑。

和设计稿的出入（2e）：

- **壁画不是单独一种家具**：设计稿说「墙上可以挂壁画（一件不挡路、挂在墙上的家具）」。现在就是现有的画框、海报（本来就挂在墙上、不挡路），每一件可以放自己的图片；地毯也可以。
- **页面画不出来时不再说「服务没在运行」**：以前画家时出错也会被当成连不上服务。现在只有真的连不上才显示那句，画的时候出错写在浏览器控制台里。

和设计稿的出入（2d）：

- **压缩过的模型先不收**：设计稿说带上 Draco 解码器。现在用了 Draco 或 meshopt 压缩的 `.glb` 会被拒绝，并提示导出时关掉压缩；以后真遇到 Tripo 默认压缩再加解码器。
- **场景加了一个柔和的环境光**（three.js 的 RoomEnvironment）：glTF 默认材质是金属，没有东西可反射时整个模型是黑的。加了以后上传的测试模型颜色正常，原来的家具看起来没变。
- **挂着功能的家具不能直接删**：先把功能都去掉再删（设计稿 home.md 说工具家具不能删，这里按「挂着功能」判断）。纸箱不能删也不能改功能，跟着工具走。
- **多了排以后，客厅大门朝着新的走廊**：出门时会经过新加的那一排旁边。房子的外形以后可以再调。
- **侧栏只在家里有变化时重画**：原来每 5 秒刷新一次会把正在选的下拉框清掉。
- 成员身体换模型不在 2d 里，按原计划是单独的「换模型」那一步。

和设计稿的出入（2a–2c）：

- **功能连接写成字符串列表**：`"video.watch": ["tool:video"]`，不是设计稿里的 `[{"by": "tool:video"}]`，少一层，意思一样。
- **2c 的「拆箱」是在「工具」页面把它连到一个功能**；把纸箱拆成一件新家具摆到别的房间，要等 2d 的家具管理页。
- **Grok 的工具调用不一定带工具 ID**：Grok 报 MCP 调用时只有一个笼统的 `use_tool`，事件里有服务器名就用，没有就不走过去。手上没有真实的 Grok 输出样本，所以没验证过它到底带不带。
- **修了第 1 步留下的问题**：改名以后，设置里内置的看视频、读网页工具还指着旧的 `src/roundtable/mcp_servers/`，从 10 月 30 日 05:37 重启到 06:23 这段时间这两个工具起不来。现在读设置时自动改成新路径（别人从 tg-roundtable 升级也一样），重启后两个工具都能正常列出工具。
- **座位提前到了 2a**：页面已经从家具的 `uses` 取座位（看东西坐电脑桌、玩游戏坐朝着电视的沙发、睡觉躺自己的床、歇着坐不是电脑桌的地方，没座位就在房间里站着）。2b 剩下的是后端按功能选家具和房间：电视挪到卧室，她看视频就去卧室。
- **座位高度写在 `uses` 里**（`"y": 0.05`），没交给模板。
- 为了让默认摆法过得了检查，有两处和原来不一样：厨房的橱柜原来横穿门口，现在靠左墙；客厅的沙发原来挡着后门，后门挪到左边（门可以写 `"at"` 指定位置）。房间换成整数格以后，走廊从 1.4 变成 1.5 个单位，比例稍有变化。总体方向见 `docs/nookling.md`，家的其余部分见 `docs/home.md`。

## 三样东西

| 名字 | 是什么 | 存在哪 |
| --- | --- | --- |
| **家具种类**（type） | 一种家具长什么样、多大、能怎么用、默认带什么功能。可以分享 | 内置的在代码里；阿明做的在 `home.json` 的 `types` |
| **摆放**（piece） | 某一件家具：哪个房间、哪一格、朝哪、挂了哪些功能 | `home.json` 的 `pieces` |
| **功能连接**（function） | 一个功能名由谁来做：内置能力，或某个 MCP 工具 | `settings.json` 的 `functions` |

功能连接放在设置里而不是 `home.json`，因为它指向工具服务器，和工具设置、密钥是一伙的；家具只认功能名。

## 尺寸和坐标

- **一格是 0.5 个单位**，一个单位大约一米（现在方块小人大约 1.5 个单位高）。
- 房间大小用格数：`"size": [10, 10]` 是 5×5 单位。
- 家具占的地方用格数：`"size": [4, 2]` 是宽 4 格、深 2 格；高度用单位：`"height": 0.9`。
- **摆放位置是房间里的格子**：`"at": [3, 1]` 是家具占地的左上角在第 3 列、第 1 行（从房间左上角数，0 开始）。
- **朝向**：`"turn": 0 | 90 | 180 | 270`。`0` 是家具的正面朝向房间的「下面」（离看的人近的那面），顺时针转。转 90/270 时占地的宽和深对调。
- 家具自己的坐标：以占地左上角为原点、正面朝下，单位是格。用途里的位置都按这个写，转向时由应用一起转。

## 家具种类

```json
{
  "id": "base/sofa-3",
  "name": "三人沙发",
  "template": "sofa",
  "size": [6, 2],
  "height": 0.9,
  "color": "#8d6e63",
  "model": null,
  "blocks": true,
  "uses": [
    {"pose": "sit", "at": [1, 1], "face": 0},
    {"pose": "sit", "at": [3, 1], "face": 0},
    {"pose": "sit", "at": [5, 1], "face": 0}
  ],
  "screen": null,
  "functions": [],
  "tags": ["客厅"]
}
```

- **`id`**：`来源/名字`。内置的是 `base/…`，阿明自己做的是 `mine/…`，包里的是 `包名/…`。全家唯一。
- **`template`**：用哪个内置的样子画（见下面的清单），按 `size`、`height`、`color` 伸缩。有 `model` 时用模型。
- **`model`**：`{"file": "sofa.glb", "turn": 0, "scale": 1}`，上传的模型，规则同 `docs/home.md`「以后换成真的 3D 模型」。没有就是 `null`。
- **`blocks`**：挡路吗。地毯、画、海报不挡。
- **`uses`**：人能在这件家具上做什么，每一项是一个位置：
  - `pose`：`sit`（坐）、`lie`（躺）、`stand`（站着用）。
  - `at`：在家具自己坐标里的位置（格，可以是小数）。
  - `face`：人朝哪，相对家具正面的角度；`0` 是和家具正面同向（坐在沙发上看前面）。
  - 坐、躺时人的高度由模板给（沙发座面、床面的高度）。
- **`screen`**：有屏幕的家具写 `{"face": 0}`，表示屏幕朝正面。别的家具上「坐」的位置如果朝着它、在同一个房间、离它不超过 8 格，就算能看到。
- **`functions`**：这种家具默认挂的功能名。摆出来时复制到摆放上，之后可以改。
- **`tags`**：给家具管理页筛选用（客厅、卧室、装饰……），不影响行为。

### 内置模板（2a 先做现在已有的，2d 补齐）

床、书桌、椅子、电脑（带显示器的书桌）、书架、衣柜、台灯、落地灯、植物、地毯、沙发、单人沙发、茶几、餐桌、电视（带电视柜）、游戏机、懒人沙发、冰箱、灶台/柜台、纸箱、画框、海报、门。大约 20 种，都是几何体拼的，按尺寸和颜色伸缩。

现在 `home.js` 里写死的家具全部变成这样的内置种类（`base/bed`、`base/desk`、`base/computer-desk`、`base/bookshelf`、`base/tv`、`base/sofa-3`、`base/fridge` ……），原来写死的座位变成它们的 `uses`。

## 摆放

```json
{
  "id": "p-7f3a",
  "type": "base/sofa-3",
  "room": "living",
  "at": [2, 1],
  "turn": 0,
  "color": null,
  "name": null,
  "functions": [],
  "added_by": "owner",
  "owner": ""
}
```

- `color`、`name` 为空时用种类的；填了就是这一件自己的（同一种沙发，一件红一件蓝）。
- `functions`：这一件挂了哪些功能名，比如电视 `["video.watch"]`、电脑 `["chat.telegram", "web.read"]`。一件可以挂好几个。
- `added_by`：`owner` 或成员 ID，第 4 步她们自己摆东西时用。
- `owner`：属于谁。卧室里的床、日记本写主人；空是大家的。睡觉时她去自己的床，没有就去自己卧室里任意一张。
- 检查：不出房间、不和别的挡路家具重叠、不挡门（门口前方 2 格留空）。不合格的拒绝并说明哪里不行。

## 功能名

形如 `领域.动作`。内置的这些先定下来：

| 功能名 | 是什么 | 默认由谁做 |
| --- | --- | --- |
| `web.search` | 联网搜索 | 成员自带的搜索（CLI 自带） |
| `web.read` | 读一个网页 | 内置的读网页工具 `reader` |
| `video.watch` | 看视频（字幕、画面） | 内置的看视频工具 `video` |
| `game.play` | 玩游戏 | 内置的游戏（现在是《杀戮尖塔》） |
| `draw.picture` | 画画 | 能画画的成员自己 |
| `chat.telegram` | 用 Telegram 和外面聊 | Telegram 应用 |
| `diary.write` | 写日记 | 内置，日常活动后自动 |

阿明接的 MCP 工具可以连到这些名字上（比如一个能看 B 站的工具连到 `video.watch`），也可以起新名字（`music.play`、`weather.check`）。

```json
"functions": {
  "video.watch": [{"by": "builtin:video"}, {"by": "tool:bili"}],
  "music.play": [{"by": "tool:netease-music"}]
}
```

- 一个功能可以由几样东西做；一个工具可以连到几个功能名。
- **能不能用，还是看工具设置里给了谁**（`members`）。家具和功能名只决定「用的时候走到哪」和「画成什么样」。
- 新接一个 MCP 工具、还没连到任何功能名时，应用自动给它起名 `tool.<工具 ID>`，并在储物间放一个纸箱挂着它（「还没拆箱：某某」）。阿明拆箱时选房间、样子，或者把它连到已有的功能名上。

## 她用东西时走到哪

1. 知道她要用哪个功能：
   - 日常活动选好动作时：读网页 → `web.read`，看视频 → `video.watch`，玩游戏 → `game.play`，往群里发 → `chat.telegram`。
   - 她调用某个 MCP 工具时：CLI 会报出工具服务器 ID，查 `functions` 找到对应的功能名。**现在这个报告只在群聊里有、而且只是一句给人看的话（「正在用某某」）；2c 要改成带上服务器 ID，并且日常活动的调用也接上。**
2. 找挂着这个功能的家具：先找她现在所在房间的，没有就找最近的，都没有就退回现在的按房间规则（看东西去书房……）。
3. 在这件家具上找空位置：
   - 它自己有 `uses`（电脑书桌带一把椅子）：用第一个空的。
   - 它是屏幕（电视）：找同一房间里朝着它、离它不远的空座位（沙发）；没有就站在它前面 2 格。
   - 都没有：站在它正面前 1 格。
4. 有人占着就换下一个；全满了就站在旁边。
5. 用完留在那儿，和现在一样。走过去只是画面，不等走到才开始用。

## 房间

```json
{"id": "living", "name": "客厅", "icon": "🛋️", "shared": true, "owner": "",
 "size": [18, 12], "floor": {"color": "#f6ead7"}, "walls": {"color": "#d9d4cc"}, "doors": ["back", "front"]}
```

- 2a 先把现在的房间大小写进来，排列方式不变。
- 2d 起房间大小可调、可以加房间，房子按排长大（规则见 `docs/home.md` 第 5 节「房子会长大」）。
- 2e 起 `floor`、`walls` 可以是颜色或图片（地砖、墙纸），墙上可以挂壁画（就是一件不挡路、挂在墙上的家具）。

## 旧数据怎么过来

- `home.json` 没有 `pieces` 时，按现在的样子自动摆一套默认家具（就是现在 `home.js` 里画的那些），每人卧室一张床、一张书桌、一本日记本。
- 页面画出来的样子要和现在一样：2a 的验收就是前后截图对比。
- 位置（`where`）、外形、翻日记记录不动。

## 接口（管理页用）

- `GET /api/home` 多返回 `types`（内置 + 自己做的）和 `pieces`。
- `POST /api/home/pieces`、`PUT /api/home/pieces/{id}`、`DELETE /api/home/pieces/{id}`：摆、挪、删（2d）。
- `POST /api/home/types`、`PUT/DELETE /api/home/types/{id}`：做自己的家具种类（2d）。
- 功能连接在「工具」页面和家具管理页里改，存进 `settings.json`（2c）。

## 分几块做

| 块 | 内容 | 验收 |

| **2a** | 内置种类、`pieces`、默认摆放、页面照数据画、房间带大小 | 前后截图一样；重启后家具还在；格子越界、重叠、挡门的摆放被拒 |
