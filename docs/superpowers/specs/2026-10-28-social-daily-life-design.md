# 自主日常和群友接话

用户已确认：按讨论中的兴趣分工，让成员自己浏览视频和帖子、聊喜好和日常、吐槽及互助。2026-10-28 的“那几项可以先落地”和“都没问题”授权本次实现。

## 范围

- 随手浏览不需要建立持续事项；结果是带来源的私人见闻，可明确选择分享或私聊。
- 持续事项表示主动想追的内容，连续探索三次后暂停；可以明确恢复，旧数据和记忆保留。
- 分享要有具体内容和可能感兴趣的人。延续现有来源摘记、可见范围、链接去重和公开发言限制。
- 私聊允许向有浏览能力的朋友求助。每段私聊至多一次额外查看，使用帮助者现有工具；结果仅进入双方的私聊，不能变成全员知识。
- 分享后的第一位响应者与分享者可以继续两次接话；PASS、睡眠、失败、每人上限和用户插话仍可结束它。
- 选人可以参考已配置的兴趣，明确点名仍优先。角色兴趣按已确认的四人分工校准，保留独立人设。

## 方案

只改提示词不足以解除“探索必须绑定事项”和短接话预算的限制。本次采用修改现有 life、room、moderator 流程的方案，不增加模型总导演、向量库、情绪数值或新工具依赖。

## 约束

Python 3.11+；不新增依赖。不调用真实模型或往 Telegram 发测试消息。保留本次开始前的未提交修改。不清空群聊、私聊、见闻或用户自定义角色。兴趣配置的应用必须备份且只改讨论过的字段；若当前进程不能访问或数据目录不可写，提供可审查的应用入口并明确生效状态。

## 验收

脚本化模型输出驱动真实 LifeStore / LifeEngine / ChatRoom，验证轻浏览跨重启保留、不会自动升级为事项、分享只带选中来源、私聊互助不外泄、对话延续有界、旧数据兼容。运行项目完整 pytest。真实模型的聊天质量需要后续日常使用观察，不能由单元测试保证。
