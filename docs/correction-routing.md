# 澄清消息的当事人优先

2026-10-28 的实际案例：“不是你记错了，是你学姐刚才忘了”。历史消息的 mentions 为空，“学姐”不在 Claude 的别名中；距离上一条回复又已超过普通接话推断的十分钟窗口，于是进入随机调度。Grok 的活跃权重为 2，Claude 为 0.5。Claude 实际会话输入中没有发现这句澄清，私聊回忆修复因此没有机会被这一句触发。

修改：

- Claude 的既有别名中补充“学姐”。其它活跃度和轮数配置保留。
- 只用公开消息、配置好的称呼和近期公开发言识别纠正对象。对于“不是 A 记错，是 B 忘了”优先 B；明确 @ 别人或使用 Telegram 回复功能时保留明确指定的对象。否定、引用和有歧义的称呼不额外推断，无法确认的情况沿用普通调度。
- `Message.recheck_targets` 保存核对对象，旧聊天记录不需要重写。每次命中也会写一条不含私聊内容的调度日志。
- 当事人不经过随机跟进概率，先收到“核对相关消息和自己的记忆，再自然回应”的提示。既有每轮私聊检索负责把本人参加过的记录送入实际模型输入，调度器本身不读取他人的私有记忆。
- 核对进行中，旁观者等待；当事人结束后恢复普通接话和明确点名交接。PASS、失败不会反复催同一个人。用户中途另点一位时，新请求可立即继续；旧回复尚在执行时到达的新澄清也有自己的核对机会。
- 普通闲聊保留原有活跃度、概率和并发。此规则不等于让所有被提及的角色都强制发表意见。

验证：373 项完整测试通过。原场景的隔离回放由真实 Claude 生成第一条回复，确认自己在 19:09 的私聊中讲过故事；Grok 没有抢答。回放使用本地测试接收端，未向 Telegram 群发送测试消息。
