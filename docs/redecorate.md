## 设计

### 什么时候改

- 日常里加一个不常出现的动作「改改家里」（`home`）：她想动动家里的时候选它。和别的动作一样由她自己决定；一周最多 3 次（许愿不算）。
- 选了以后，给她看：「家里现在」、她自己卧室里每一件东西（名字、靠在哪、朝哪）、她要动的那间公共房间里的东西、她这周还能做几次、能用的家具种类清单。她输出一次要做的事（最多 3 件小改动），应用检查后照做，做不成的说明原因、记下来。
- 群聊和家里聊天时不直接改；聊着聊着想要什么，可以在回复末尾加一个心愿标记 `[心愿:想要什么|为什么]`，进心愿单（见下）。

### 她怎么说「放在哪」

模型说不准格子坐标，所以用话说，应用去找格子：

- 放哪间房，然后：靠哪面墙（后、前、左、右）、在哪件东西旁边、或者放中间；挂墙的说挂哪面墙、高一点还是低一点。
- 朝向：朝房间里面（靠墙的默认这样）、朝哪件东西（比如沙发朝电视）。
- 应用按这些找最近的放得下的位置（不挡门、不叠、不在楼梯口），找不到就告诉她「靠窗那面墙放不下了」。

### 她自己能做的、要阿明同意的

| 想做的事 | 自己做 | 要阿明同意 |
| --- | --- | --- |
| 自己卧室：加东西、挪、转、换颜色、改名字、扔掉 | ✓ | |
| 自己卧室改名、换地板和墙的颜色 | ✓ | |
| 公共房间：挪家具（房间里换位置，包括挂墙的） | ✓ 每间房一周最多两次 | |
| 公共房间改名 | ✓ 每间房一周最多一次 | |
| 公共房间：加东西、扔东西 | | ✓ |
| 把家具搬到另一个房间（比如把电视搬进自己卧室） | | ✓ |
| 新房间（「想要一间自己的书房」） | | ✓ |
| 让一件家具带上功能（比如卧室里的电视能看视频） | | ✓ |
| 新本事（「想要一台能放歌的唱片机」） | 只能许愿 | 阿明接一个 MCP 工具，再给它安排家具 |

- 她加的东西从家具种类清单里选（内置的和阿明做的），可以起名字、选颜色；**不带功能**——功能是阿明分配的，要带功能就许愿。
- 限额：卧室最多 16 件；一次最多 3 件小改动；一周最多改造 3 次；名字最长 8 个字。
- 房间的内部编号不变，改名不影响任何东西。

### 心愿单

- 一条心愿：想要什么、为什么、和哪间房有关；能看懂的话顺便带上具体内容（要哪种家具放哪间房、要多大的房间），这样阿明点「同意」就能自动做好。
- 「家」页面侧栏多一页「心愿」，阿明可以：
  - **同意**：能自动做的自动做好（加家具、搬家具、加房间，房间放在挨着走廊的空地上，自动开门）；不能自动做的（新本事）阿明自己去做，点「做好了」。
  - **改一改再同意**：比如书房给小一号、家具换个房间。
  - **不同意**：写一句为什么。
- 她下次说话或做日常时会知道结果（同意了、改过了、为什么不同意），一次。不同意的过几天可以换个说法再许。
- 每人同时最多 3 条没处理的心愿。

### 别人会知道，阿明能撤回

- 每次改造记进「家里的变化」：谁、什么时候、动了什么（「Codex 把客厅的沙发挪到靠窗那面墙」「Grok 把娱乐室改名叫『牌桌』」）。
- 其他家人下次说话或做日常时看到一句（每条只看到一次），可以喜欢、吐槽、下次挪回去。「家里现在」本来就是最新的，所以她们说起家里不会说错。
- 页面上能看到「家里的变化」，阿明能撤回任何一次（恢复成改之前），撤回也记下来，改的人会知道。

## 对其他部分的影响

- **只改 `home.json`**：所有改动都走现在的检查（放得下、不挡门、不叠、楼梯口、挂墙规则），不碰代码，不碰阿明电脑上的任何文件。
- **日常**：多一个动作，多一段提示；不常选（提示里说清楚「想动的时候才动」）。
- **花费**：一次改造是一次日常活动，不另外花。
