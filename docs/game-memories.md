# 游戏情绪记忆：从玩过的局里长出心情和看法

2026-10-29。适用于现在的《杀戮尖塔》接入（`src/roundtable/games/`），以后接别的游戏也沿用同一套记忆格式。

**实现状态（2026-10-29）**：下面五个阶段都已实现，见 `games/story.py`、`games/spire_tags.py`、`game_memories.py`，接入点在 `Runtime._record_game` / `_remember_climb`，测试在 `tests/test_game_memories.py`。和设计稿的出入：

- 段落记忆没做，只在一局结束时生成（待定问题的默认答案）。
- 写记忆用 `_chronicle_writer` 选出的最便宜成员（有 DeepSeek 就是它）；只剩 Claude 时不调模型，直接用模板句。
- 卡牌标签表里的 id 按游戏内部名写；真实记录里目前只出现过基础牌，`Shrug It Off` 等已核对，其余待实玩出现后再核对。
- 修改记忆用 `PUT /api/game-memories/{id}`（和项目里其他接口一致），钉住/隐藏/恢复是 `POST /api/game-memories/{id}/pinned|hidden|active`，清空看法统计是 `DELETE /api/game-opinions/{member}/{subject}`。
- 群梗提名直接放进梗库，状态是关闭，在梗库里打开才生效。
- 已有的游玩回执不回填；从这版上线后开始的局才会被串成一局、生成记忆。

## 为什么要做

现在每次游玩结束，`Runtime._record_game` 存一份**事实回执**：操作步数、楼层、生命、打赢的楼层，外加 `highlights()` 挑出的最多 6 条「第 N 层获得某牌 / 使用某牌，当时想法：……」。群聊里有人提到「游戏」「杀戮」「玩了」时，`LifeLog.game_recall` 把最近 2 次回执塞进提示。

这样成员能说清**做了什么**，但说不出：

- **当时什么感受**：流派成型时的兴奋，等不到关键牌的郁闷，没成型就死了的遗憾。
- **跨局形成的看法**：「毒流好玩但看脸」「这个 Boss 我打一次死一次」。
- **这些经历怎么改变下一局**：想再试一次上次没成的流派，或者绕开那个老是打死自己的敌人。

每局都是孤立的流水账，不会累积成性格。

## 目标

1. 每局（或每段游玩）结束后，生成 1–3 条带情绪的**经历记忆块**，内容有事实依据。
2. 情绪会随时间淡去；反复出现的经历沉淀成长期的**看法**（偏好、怨念、迷信）。
3. 记忆在合适的时候被想起：群里聊到相关的东西、别的成员也遇到同一个敌人或流派时。
4. 看法反过来影响下一局怎么玩，让每个成员的打法随经历变化，而且各不相同。
5. 管理页能看、能改、能删这些记忆。

## 不做

- 不让模型凭空编情绪或经过。事实由代码从操作记录里算出来，模型只负责「怎么说」和「是什么感受」。
- 不把记忆当成发言任务。想起来不等于要说，和现有的 `game_recall` 提示一致：「这些是经历线索，不是安排给你的发言任务」。
- 本地回放（`publication_target == "local_preview"`）不产生记忆，和 `_record_game` 现在的规则一样。

## 一局 vs. 一段游玩

现在一次 `GameService.play` 往往只打一场战斗就停（`stop_after_battle`、`decisions`、`minutes` 限制），靠游戏自己的检查点下次继续。所以一份回执只是**一段游玩**，真正的一局（从第 0 层爬到死或通关）跨好几份回执。

需要补一个**局 ID**（`climb_id`）把同一局的回执串起来：

- 回执 `first.floor == 0` 且 `screen_type` 为开局画面 → 新开一局，生成新的 `climb_id`。
- 否则沿用该成员上一份未结束回执的 `climb_id`（有 `checkpoint_available` 且上一份不是 `game_over`）。
- `game_over` 或通关 → 这一局结束。

记忆分两种时机生成：

- **段落记忆**（每段游玩后，可选）：只在有明显事件时生成，比如差点死了、拿到了关键牌。
- **整局记忆**（一局结束时，必做）：回看整局，判断流派成没成、死在哪、和以前比怎么样。

## 第一步：代码提取「剧情信号」

新模块 `src/roundtable/games/story.py`，输入一局所有段落的 `actions.jsonl` 事件（字段见 `visible_state`：`deck`、`relics`、`combat_state.monsters`、`screen_state`、`reason`），输出结构化信号。全部是确定性计算，可单测。

| 信号 | 怎么算 |
|---|---|
| 流派 | 按卡牌 `id` 查标签表（见下），统计牌组里各标签的牌数；某标签 ≥ 3 张且有核心牌 → 记为「在走这个流派」；有核心牌和 ≥ 2 张配合牌 → 「成型」。 |
| 成型楼层 | 流派第一次达到「成型」时的楼层。 |
| 想要没来的牌 | 决策 `reason` 里反复提到同一张牌（≥ 3 次），而选牌奖励里一直没出现过（`CARD_REWARD` 的 `screen_state.cards`）。 |
| 死因 | `GAME_OVER` 前最后一场战斗的怪物名、进战斗前的生命、死在第几层第几幕。 |
| 险胜 | 战斗结束时生命 < 最大生命的 15%。 |
| 关键一手 | 一回合内把敌人从 > 30% 血打到 0，或一张牌带来的伤害/格挡超过当回合总量的一半。 |
| 跳过的牌 | 选牌奖励选了跳过（说明在挑，有方向）。 |
| 和以前比 | 本局最高楼层 vs. 该成员历史最高；同一怪物第几次杀死自己。 |

卡牌标签表先只做铁甲战士（目前只开放这个角色），放在 `games/spire_tags.py`，例如：

```python
IRONCLAD_TAGS = {
    "力量": {"core": ["Inflame", "Spot Weakness", "Limit Break", "Demon Form"],
             "support": ["Heavy Blade", "Sword Boomerang", "Twin Strike", "Pummel", "Whirlwind"]},
    "消耗": {"core": ["Corruption", "Feel No Pain", "Dark Embrace"],
             "support": ["Second Wind", "Burning Pact", "True Grit", "Sever Soul", "Fiend Fire"]},
    "格挡": {"core": ["Barricade", "Body Slam", "Juggernaut"],
             "support": ["Entrench", "Impervious", "Flame Barrier", "Shrug It Off", "Power Through"]},
    "自伤": {"core": ["Rupture"], "support": ["Bloodletting", "Offering", "Hemokinesis", "Combust"]},
}
```

表里用游戏内部 `id`（英文），展示时用 `deck[].name`（中文）。表不全没关系：认不出的牌只是不计入流派。

## 第二步：把信号写成记忆块

一局结束后，调用一次 **DeepSeek**（便宜，走 API；**不用 Claude**，Claude 用的是主人写代码的额度）。成员是谁就用谁的角色卡和口吻，输入只有第一步的信号 JSON 加该成员最近几条同类记忆，输出 1–3 个记忆块：

```json
{
  "id": "m_8f2c…",
  "member": "grok",
  "game": "slay-the-spire",
  "climb": "c_20261029-grok-1",
  "kind": "流派",
  "subject": "力量流",
  "feeling": "遗憾",
  "intensity": 0.7,
  "story": "拿了燃烧想走力量，一直没等到重刃，第二幕被铜器人磨死了",
  "facts": {"floor": 22, "act": 2, "killer": "铜器人", "build": "力量", "formed": false},
  "tags": ["力量", "燃烧", "重刃", "铜器人"],
  "at": 1793257310.2,
  "status": "active"
}
```

- `kind`：`流派`（这次走了什么、成没成）、`遭遇`（某个敌人或事件）、`手气`（等不到的牌、天降神牌）、`时刻`（险胜、关键一手）、`成绩`（新纪录、最快死亡）。
- `feeling`：从一个固定小表里选——兴奋、得意、满足、遗憾、郁闷、不服、记仇、后怕、无语、好笑。固定词表方便衰减、统计和管理页显示。
- `story`：一句话，≤ 40 字，成员自己的口吻。只能用 `facts` 里有的东西；校验时 `story` 里出现的牌名、怪物名、楼层数必须能在 `facts`/信号里找到，否则丢弃重写一次，再不行就用模板句。
- `intensity`：0–1。模型给初值，代码再按信号修正：新纪录、第三次死在同一个怪手里这类自动加分。

整局没什么可说的（比如第 2 层就退出了）就不生成，宁缺毋滥。

## 第三步：情绪会淡，看法会留

**衰减**：读记忆时算当前强度 `intensity × 0.5 ** (天数 / 3)`，即半衰期约 3 天。不改存储，只在读的时候算。

**当前心情**：当前强度 ≥ 0.4 的记忆，取最强的 1–2 条，写成一句话放进该成员的系统提示：

> （你最近的游戏心情：昨晚力量流没成型，死在铜器人手里，有点不服。）

影响的只是语气和想不想提，不要求发言。现有的「可以不营业」规则照样适用。

**看法**：每个成员维护一张按主题汇总的表（`subject` → 统计），记忆一写入就更新：

```json
{"力量流": {"tries": 4, "formed": 1, "deaths": 3, "best_floor": 33, "feelings": {"遗憾": 2, "兴奋": 1}},
 "铜器人": {"met": 3, "killed_me": 2}}
```

再由代码按阈值生成固定措辞（不调模型）：

- 试了 ≥ 3 次、成型率 < 30% → 「觉得 X 太看脸」
- 成型过且那次打得最远 → 「最喜欢 X」
- 被同一个敌人杀 ≥ 2 次 → 「跟 Y 有仇」
- 同一张牌出现在 ≥ 2 局的「想要没来」里 → 「每次都等不到 Z」

看法放进系统提示的「你自己的日常记忆」那一段（`LifeLog` 渲染处），最多 3 条，按最近更新时间排序。

## 第四步：什么时候想起来

替换现在 `game_recall` 的「关键词正则 + 最近 2 次」：

1. 用 `recall.topic_score` 拿当前聊天去匹配记忆的 `tags`、`subject` 和 `story`，得分 > 0 的按「得分 × 当前强度」排序，取前 2 条。
2. 聊天里出现游戏相关词（沿用现在的正则）但没匹配到具体记忆时，退回「最近一局的整局记忆」。
3. **别人的记忆也能触发自己的**：群里 A 说到铜器人，B 也有关于铜器人的记忆时，B 的回合也带上这条。这一步是群里「你也死在它手里？」这类对话的来源。

想起来的记忆和现在一样放在 `[你的真实游玩经历]` 块里，沿用已有的真实性提示（获得和花费别搞反、没记录的胜利不要补）。

## 第五步：看法影响下一局

`_play_locked` 拼游戏决策提示时，在开头加一段该成员的「玩家性格」：

> 你以前玩过：力量流试了 4 次只成过 1 次，觉得太看脸；跟铜器人有仇；最远打到第 33 层。
> 这些是你自己的偏好，可以照着来，也可以这次偏要试试别的。

再加上角色卡本来的性格：Grok 好胜，会想复仇或者偏要再试那个没成的流派；DeepSeek 求稳；Codex 务实，喜欢稳定的格挡流。这样不同成员打出不同风格，而且会随经历变化。

只影响偏好，不影响合法动作的校验；`legal_actions` 和「模型选择了未提供的动作」的检查保持不变。

## 第六步：共同经历和群梗

- **陪玩**：`GameConversation` 里陪看的朋友也生成一条记忆，视角是旁观者：「看 DeepSeek 满血换了 75 金币，我觉得血亏」。`member` 是陪看的人，`facts` 只取他实际看到的局面（私聊里分享过的那些）。
- **成绩对比**：看法表里的 `best_floor` 让成员之间可以比。比如 Grok 最高 33 层、DeepSeek 最高 12 层，Grok 的提示里可以带一句「你目前打得最远」。
- **变成群梗**：同一类记忆在一个成员身上出现 ≥ 3 次（如「力量流没成」），把一句话提给梗库（`memes.json`），状态设为待审，由主人在管理页决定要不要收，不自动生效。群友就能拿「Grok 的力量流从来没成过」来损她。

## 存储

新文件 `H:\tg-roundtable-data\game_memories.json`：

```json
{"memories": [ …记忆块… ],
 "opinions": {"grok": { …看法表… }},
 "climbs": {"c_20261029-grok-1": {"member": "grok", "receipts": ["…"], "ended": true}}}
```

- 每个成员最多保留 200 条记忆；超出时先删当前强度最低、`status` 不是 `pinned` 的。
- `status`：`active` / `pinned`（主人钉住，不衰减不删）/ `hidden`（主人隐藏，不进提示但保留统计）。
- 写法沿用现有存储的 `atomic_json`。

## 管理页

在成员详情里加「游戏记忆」卡片，样式参考现有的「你点过赞和踩的话」：

- 每条一行：情绪图标 + `story` + 当前强度条 + 日期 + 局 ID。
- 操作：钉住、隐藏、删除、修改 `story`。
- 下面列出看法表生成的几句话。看法由统计生成，不能直接改，但可以清空某个主题的统计。

接口：`GET /api/game-memories?member=`、`POST /api/game-memories/{id}/pin|hide`、`PATCH`（改 story）、`DELETE`。

## 测试

- `story.py`：用 `games/slay-the-spire/runs/` 下的真实 `actions.jsonl` 做固定样例，断言流派、成型楼层、死因、险胜的识别结果。
- 记忆校验：故意让假模型返回编造的牌名或楼层，断言被拒绝、改用模板句。
- 衰减和心情：固定时钟，3 天后强度减半，低于 0.4 不进系统提示。
- 看法阈值：喂 4 局假数据，断言生成「太看脸」「有仇」。

- `local_preview` 回执不产生任何记忆。

## 分阶段

1. **局 ID + 剧情信号**（`story.py`、`spire_tags.py`）。纯代码，最有价值的事实底座。
2. **记忆块生成 + 存储 + 当前心情**。到这一步，群聊里已经能感觉到情绪了。
3. **看法表 + 召回替换**。
4. **看法回流到游戏决策**。
5. **陪玩视角记忆、群梗提名、管理页**。

每阶段单独可上线、可回退：记忆文件删掉就回到现在的行为。

## 打完之后：自己决定下一步（2026-10-29 加）

目标是「不是阿明让她玩她才玩」。一局结束、记忆写完后，再用一次便宜模型（同样不用 Claude），按成员的性格、当前心情、攒下的看法和这局的事实，替她说出自己的打算：

| choice | 意思 | 默认有效期 | 效果 |
|---|---|---|---|
| `again` | 马上再来一局 | 3 小时 | 电脑空闲、开了自主游玩、她今天还有活动次数时，立刻自己开下一局；否则先记着 |
| `later` | 过阵子再玩 | 1 天 | 日常里照常可以选 play，提示里带上这句打算 |
| `rest` | 这游戏先放几天 | 她说的天数（1–7），默认 2 天 | 有效期内日常里不再提供 play |
| `help` | 想问问朋友怎么打 | 2 天 | 她的 `say` 作为一句话发到群里，群友照常接话 |
| `other` | 想玩点别的游戏 | 她说的天数，默认 3 天 | 同 `rest`；`say` 可以是问阿明能不能装别的游戏 |

- 打算写进她的系统提示，聊天时她知道自己「这几天不碰尖塔」。也写进日常活动的选择提示，可以照着来，有缘由也可以改主意。
- 阿明手动开局不受限制；她在 `rest` 期间被叫去玩，游戏提示会告诉她「这次是阿明让你开的，不想玩可以 pause」。
- 之后任何一段真实游玩都会把旧打算标成已完成（`done`）。
- `say` 和记忆一样过事实检查：提到这局里出现过、但不在事实里的牌名、敌人或数字，就不发。她在睡觉（按作息）时也不发，只写日志。
- 模型答不上来时按事实给一个保守的打算：通关 → `later`；又死在宿敌手里 → `rest` 2 天；险胜或新纪录 → `again`；其他 → `later`。
- 管理页「游戏记忆」卡片里每个成员后面的 🎯 是她现在的打算。
- 存在 `game_memories.json` 的 `intentions` 里，每个成员只保留最新一条。

后续（未做）：按经历算出的「想玩度」参与自主游玩排期；求助后朋友的建议记成记忆并带进下一局；邀请朋友陪看时，朋友按自己的想玩度决定来不来。
