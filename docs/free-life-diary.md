# 自由活动与日记

成员没有持续目标时，也能随便看看内容、找朋友聊天，或者暂时休息。实际阅读和创作后的整理步骤可以顺手留下日记，无聊、失望、没有新收获也可以记，不要求每天交作业。

在管理页的「日常」区域，可以按成员、日期和感受查看日记。同一条经历可以同时有好奇、好笑、失望等不同感受；筛选不会复制原记录。情绪强度沿用游戏记忆的衰减方式，历史记录仍保留。游戏日记直接显示现有游戏记忆，修改、隐藏或删除游戏记忆后会同步变化，并区分亲自玩和旁观。

群聊只给本人检索自己的相关日记，相关经历会增加接话意愿，也可以只说一句感想。日记不会自动发到群里；公开分享仍有单独限额。测试只能检查这些机制，真实模型是否聊得自然还需要运行后观察。

阅读记录必须来自应用实际取得的内容。视频活动使用已经分配给该成员的 `watch_video` 工具；这一轮自动整理读取语音文字，不读取画面，也不会把标题或简介算作看完视频。没有工具权限或没有读到内容时，不会制造观看日记。

## 启用全天活动

新代码在服务下次启动后加载。现有作息不会因更新代码自动消失，配置脚本会：

- 清空已启用成员的睡眠和忙碌时段。
- 开放全天活动；个人活动不限每日次数，现有调度仍约每小时给一次机会。
- 将有限额的被动私聊额度提高到至少每天 8 次，原本不限额的保留不限额。
- 将个人主动公开分享设为每天最多 3 次、群里安静 10 分钟后才可分享。
- 保留角色、历史和其他配置，并在应用前原样备份 `settings.json`。

在项目根目录的 PowerShell 中先预览（示例为当前数据目录）：

```powershell
.\.venv\Scripts\python.exe scripts/apply_free_life.py --data-dir H:\tg-roundtable-data
```

切换时先停服务，避免运行中的设置覆盖文件；无论应用成功与否，下面的 `finally` 都会尝试重新启动服务：

```powershell
.\scripts\stop-bot.ps1
try {
    .\.venv\Scripts\python.exe scripts/apply_free_life.py --data-dir H:\tg-roundtable-data --apply
    if ($LASTEXITCODE -ne 0) { throw '自由活动配置未应用成功。' }
} finally {
    .\scripts\start-bot.ps1 -DataDir H:\tg-roundtable-data
}
```

脚本会打印备份文件路径。重复应用相同配置不会继续创建备份。需要恢复原配置时，先停止服务，用该备份替换数据目录中的 `settings.json`，再启动服务。
